# 附近搜索与出行

1. 使用用户提供的城市加地标、详细地址或高德坐标。同一聊天中唯一明确的出发地址可以沿用，并在回答中注明。若有多个可能起点、同名地点无法区分，或用户只说「我附近」且未提供位置，先确认。
2. 用 `nearby-amap` 的 `search_nearby_places` 生成候选。传入地点、关键词、米制半径，以及合适的 `category`（`restaurant`、`hotel` 或 `train_station`）。坐标输入用高德坐标，格式为「纬度,经度」。无距离要求时，餐厅和酒店可先查 5 公里，火车站先查 15 公里，候选不足再扩大；用户的硬性范围优先。结果的 `distance_m` 是直线距离。关键词匹配可能含相似或无关结果，需要核对。
3. 根据需求验证候选：
   - **餐厅**：用 `nearby-dianping` 的 `search_places` 按城市和关键词核对店名、分店和人均，必要时用 `get_place_details` 查营业信息。若详情解析不出，使用可访问的店铺页、官方门店页或地图核对。查指定连锁时，留意旧分店或已关门的近店，给出更近的关店信息和最近可确认营业的分店。「类似某餐厅」先抓菜品、消费和用餐风格，筛掉同名无关店；指定蓝蛙时可另提示附近的实际蓝蛙门店。
   - **万豪**：默认按万豪旅享家旗下品牌查。结合万豪官网城市目录和旗下品牌关键词找候选，再以每家酒店官网核对名称、品牌和地址，避免遗漏名称不带「万豪」的酒店，以及地图上同一酒店的多个标记。用户要求 Marriott Hotels 主品牌时，按这一品牌限定。只有明确住宿日期且查到对应日期的房价与库存，才报告该报价和可订情况。
   - **火车站**：先查「火车站」，再用铁路 12306、铁路部门或地方政府资料核对确为国铁客运站。排除货运站、地铁站和同站进出站口。用户给了目的地或日期时，按可查证的停靠车次筛选。
4. 用 `route_to_place`（`origin`、`destination`、`mode`）核对入选地点。已知地图落点时用坐标，优先使用正确门店或客运入口。「步行 N 分钟内」必须以步行路线核验；无法核验时不列作已满足。按用户指定的路程、时间或其他标准排序。驾车时间写成估算，直线距离单独标明。
5. 按用户要求的类别和数量给清单。每项尽量有店名或站名、地址、距离类型或车程、相关来源链接。用户问营业状态时注明可核实的营业时间或状态；来源冲突时简述差异。候选不足时列出已核实的数量与限制。

## 数据源不可用时

两个 MCP 新装或更改后可能需要重开 Codex 会话。高德报 Key 未配置或接口错误时，用公开地图或网页核对；无可信路线时写「路线待确认」。高德有效查询返回空结果时，检查地址和关键词，可在用户范围允许时扩圈。大众点评会话失效或要求验证时，用公开来源继续，并提示需要本机登录才能恢复点评工具。未经确认的地址、人均、营业状态或价格，标注待确认。查询范围限于检索和比较，预订等操作由用户另行提出。

示例：「上海静安寺周边找最近营业的红盔甲」「杭州东站 5 公里内找万豪旅享家酒店」「以上海静安寺为起点，各列 3 个国铁客运站、万豪旅享家酒店和类似蓝蛙的餐厅」。
